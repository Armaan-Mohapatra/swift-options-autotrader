# Phase 8 — opt-in unattended PAPER integration (GitHub candidate)

**Status: CODE_CANDIDATE / PRIOR SYNTHETIC LOCAL_TESTED / MANDATORY_CI_BLOCKED / MCP_FIELD_UNVERIFIED / NO_RELEASE.**

This extends the existing Phase 0–7 pipeline without replacing the strategy. New modules `paper_dispatch.py`, `paper_service.py` and `broker/mcp_paper_data.py` wire authorized durable Telegram events to the existing `SignalMatcher`, strict read-only exact option contracts/quotes, `PaperOrderEngine` and the concrete SQLite `PaperBroker`. No Robinhood place/cancel tool is called. Existing exact original Swift limits, 3,600-second accepted-order deadlines, LOTTO parity, no rebuy on ADD, NEW AVG metadata separation and all-matching-position exits remain unchanged.

The dispatcher **does not consume fresh unparsed source entries on missing market data**. It calls the paper-engine reconciliation/cancel watchdog with `allow_entries=False` during outages. Quote-based simulated fills require dated exact-contract prices and displayed depth; unavailable prices and unfilled orders cannot generate P&L. A five-second supervisor poll may cancel at the first tick at or after the exact 3,600-second deadline.

`MCPReadOnlyOptionData` requires unique underlying/right/strike/expiration/year, eligible external agent account, buying power, explicit positive option tick, multiplier 100, dated bid/ask and nonnegative displayed bid/ask size, option order-review result and an exchange-calendar session. The public Robinhood MCP help page confirms the **tool names**, not availability of all those fields in actual tool output. Missing tick/depth/multiplier, incompatible schema, OAuth failure or approval requirement **blocks PAPER entries**, not an excuse to fake evidence. MCP output remains unverified until independent read-only local validation. This code never implements real-money order submission.

The Windows supervisor gains an **explicit opt-in** PAPER worker, separate from its dashboard and Telegram listener. The installed configuration defaults `paper_dispatch_enabled=false`, `paper_data_source=none`, paper risk ceilings zero. It requires manually approved read-only account OAuth under user-scope DPAPI and a separately enrolled legitimate Telegram user session. The OAuth redirect callback uses `127.0.0.1:8766`; dashboard uses `127.0.0.1:8765`. The PAPER worker does not receive Telegram API hash or session data.
